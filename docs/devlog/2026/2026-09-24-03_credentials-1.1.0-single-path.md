## Why

Devlog 2026-09-24-02 established that a `DS/<app>/...` AMD id cannot resolve
from an external widget (UWA rule C6). That made the OOTB branch in
`JazzySole/Credentials` unreachable code that still cost a 404 and a
`console.info` on every single load. The user asked to keep only the working
option.

## What changed

`JazzySole/Credentials` **1.0.0 -> 1.1.0**, one path instead of two.

| Removed | Kept |
|---|---|
| `loadOotb()`, `OOTB_MODULE`, `OOTB_TIMEOUT_MS` | `getMe()`, `buildOptions()`, `readOptions()` |
| `state.source`, `info().source` | the preference key `xPref_CREDENTIAL` |
| the "OOTB path not used, fallback" `console.info` | OOTB-identical values, labels and ordering |
| "Credential source" row in `HelloView` | the rest of the public API, unchanged |

`loadFallback()` became **`loadPreference()`** - it is no longer a fallback, it
is the behaviour. `init()` dropped its redundant outer `get3DSpaceUrl()` call,
since `loadPreference()` resolves it anyway and the result is cached.

The module header now explains *why* there is no `DS/` require, with a pointer
to rule C6 - otherwise this is exactly the kind of thing someone helpfully
re-adds in six months.

## Tests

7 scenarios -> 6. The three OOTB ones (module loads / load error / timeout) do
not describe anything real any more. Added:

- user with no credential -> `init()` rejects with "No credentials assigned";
- a **regression guard**: the module source must contain no `require(` call and
  no `loadOotb` / `OOTB_MODULE` / `OOTB_TIMEOUT` identifier, and `info()` must
  not carry `source`.

The first version of that guard was too crude - it scanned a slice of the file
and tripped on a legitimate `DS/ENOXWidgetPreferences` mention in a JSDoc
comment. Narrowed it to the two precise checks above, which is also a better
statement of intent: comments explaining the limit are wanted, a `require(` call
is not.

`ALL CREDENTIALS TESTS PASSED`, `ALL ROUTER TESTS PASSED`.

## Also fixed

A stray blank line in `docs/reference/uwa-rules-and-libraries.md` had orphaned
the Credentials and Router rows out of the library table, rendering them as a
headerless table. Pre-existing, unrelated, one line.

## Expected effect in the browser

One of the two console 404s disappears. `DS/3DXContentChecker` stays - that one
is the dashboard's own `FrameExtension.js` and is not ours to fix.
